## VERIFY MINIKUBE ##
kubectl version --client
kubectl cluster-info

** If the version of client and server mismatch like:
root@minikube:~# kubectl version
Client Version: v1.35.0
Kustomize Version: v5.7.1
Server Version: v1.30.0
Warning: version difference between client (1.35) and server (1.30) exceeds the supported minor version skew of +/-1

--> Then , we can delete the minikube cluster with:
minikube delete
(IF IMAGES OR OTHER THINGS ARE CONSUMING MORE ON SERVER, THEN WE CAN SIMPLY PRUNE THOSE ALL:)
docker system prune -a --volumes <OR> docker system prune -a

and specify the kebernetes version in same command as below:
minikube start --kubernetes-version=v1.34.0

and now, if we check the version then no warning.
kubectl version

** If wanted to run as root user, which is not recommended, then run below:
minikube start --driver=docker --force

## We have option to access the minikube from GUI since we have dashboard feature 
--> If running the Ubuntu machine as GUI, then directly run below:
(you might require to enable the metric server to get the usage data on dashboard, it will give you suggestion if not enabled as below, then run the same in another terminal or console, and access the URL to get the dashboard into browser)
path4cloud@minikube2026:~/kubernetes$ minikube dashboard
* Enabling dashboard ...
  - Using image docker.io/kubernetesui/dashboard:v2.7.0
  - Using image docker.io/kubernetesui/metrics-scraper:v1.0.8
* Some dashboard features require the metrics-server addon. To enable all features please run:

        minikube addons enable metrics-server

* Verifying dashboard health ...
* Launching proxy ...
* Verifying proxy health ...

* Opening http://127.0.0.1:43483/api/v1/namespaces/kubernetes-dashboard/services/http:kubernetes-dashboard:/proxy/ in your default browser...
  http://127.0.0.1:43483/api/v1/namespaces/kubernetes-dashboard/services/http:kubernetes-dashboard:/proxy/


--> If running the Ubuntu machine inside the VM in your local system, then we need to set the prot forwarding via proxy and then with VM IP, from our local system, dashboard can be accessed:
path4cloud@minikube2026:~/kubernetes$ kubectl proxy --address='0.0.0.0' --disable-filter=true
W0327 17:52:22.170015   32008 proxy.go:177] Request filter disabled, your proxy is vulnerable to XSRF attacks, please be cautious
Starting to serve on [::]:8001

(now, run the minikube dashboard on another terminal and it will give you the URL, if already ran that dashboard command then with this command, we can get the URL again # minikube dashboard --url)
and we can access the dashboard with VM_IP:8001

http://<VM_IP>:8001/api/v1/namespaces/kubernetes-dashboard/services/http:kubernetes-dashboard:/proxy/
